# The format of giac-openmath.toml

`giac-openmath.toml` is the source; `giac-openmath.json` is the same data as
JSON, generated by `just export` (keys sorted), for consumers without a TOML
reader. A test fails if the two differ.

## Top level

| Key | Meaning |
|---|---|
| `format` | Version of this format: 2 (format 1 had no statuses, private CDs or procedures). |
| `giac_version` | The GIAC the tests in `test/giac` ran against. Node names are GIAC's at that version. |
| `cd_source` | Where the Content Dictionaries come from: `repository`, the pinned `commit`, and `raw`, a URL template with `{commit}` and `{path}`. |
| `cd.<name>` | Each Content Dictionary used: its `path`, the `sha256` of the file, and the `status` the file declares (`official`, `experimental` or `private`). A private CD of JuliaGiac is a file of this repository (`local = true`, path under `docs/cd/`) with its own `cdbase`. |
| `leaf` | GIAC values that are not calls, and their OpenMath symbols. |
| `map` | GIAC calls and their OpenMath forms. |
| `refused` | What is not mapped, on purpose, and why. |
| `envelope` | The symbols of a request to GIAC and of its answer (`scscp1.procedure_call`, `procedure_completed`, `procedure_terminated`, `info_message`, `error_system_specific`), and `procedure_cds`, the CDs whose symbols are requests (`giac_procedures1`, `prog1`). |
| `procedure` | Requests to GIAC: a GIAC pattern and the OpenMath pattern, like a map, with a head in one of the `procedure_cds`; valid only inside the envelope's call. |
| `procedure_option` | Options of a request and the GIAC setting each sets: premises and complex mode (semantic attributions on the call's argument), time limit (`scscp1.option_runtime`, on the `procedure_call` application). |

## Which GIAC names

The `giac` side is GIAC itself, the C++ library: a node name is the name of
the operator at the root of GIAC's expression tree (`symb_funcname` in
Giac.jl, the `unary_function` name in C++). It is not always the name typed
in GIAC's input:

- some input names are read as another node, and are listed as `aliases`:
  `log(x)` is the node `ln`, `arcsin(x)` the node `asin`;
- evaluation changes trees: `x/y` becomes `*(x, inv(y))`, `x-y` becomes
  `+(x, -(y))`, `sqrt(x)` becomes `^(x, 1/2)`, `f(x)` is `of(f, x)`. The table
  maps the nodes found in both unevaluated and evaluated trees; the notes say
  what GIAC rewrites;
- a few node names are not identifiers: `+`, `^`, `==`, and `" xor "`, with
  its spaces.

## Leaves

```toml
[[leaf]]
giac = "pi"          # a GIAC identifier or constant, as GIAC reads it
om = "nums1.pi"      # an OpenMath symbol, "cd.name"
direction = "both"   # optional: both (default), to_openmath, from_openmath
note = "…"           # optional
```

What no entry covers follows these conventions:

| GIAC | OpenMath |
|---|---|
| integer (`INT`, `ZINT`) | `OMI` |
| fraction `p/q` (`FRAC`) | `nums1.rational(p, q)` |
| complex `a+b*i` (`CPLX`) other than `i` | `complex1.complex_cartesian(a, b)` |
| identifier (`IDNT`) not in a leaf entry | `OMV` of the same name |
| float (`DOUBLE`, `REAL`) | `OMF`; inexact, a consumer may refuse it |

Anything else (lists, strings, programs, units…) is refused.

## Maps

```toml
[[map]]
giac = ["logb", "#1", "#2"]          # GIAC pattern: node name, then arguments
om = ["transc1.log", "#2", "#1"]     # OpenMath pattern
input = "call"                       # optional: call (default), infix, prefix
aliases = []                         # optional: other names GIAC reads as this node
direction = "both"                   # optional: both (default), to_openmath, from_openmath
status = "names"                     # optional: names (default), checked
note = "…"                           # optional
```

### Patterns

In both patterns:

- `"#1"`, `"#2"`… are the arguments of the GIAC node, in order; `"#*"` is all
  of them (at the end of the GIAC pattern only). Each placeholder appears on
  both sides: no argument is dropped or invented.
- An integer is that integer: in a GIAC pattern it must be there (`limit`'s
  direction `1` or `-1`); in an OpenMath pattern it is an `OMI`.

In a GIAC pattern, any other string is a GIAC identifier that must be there
(`["+", "infinity"]` is GIAC's `+infinity`). A consumer tries patterns with
such literals before the general ones.

In an OpenMath pattern:

| Pattern | OpenMath |
|---|---|
| `"cd.name"` | `OMS` |
| `["cd.name", a, b, …]` | `OMA(OMS, a, b, …)` |
| `["apply", f, a, …]` | `OMA(f, a, …)`, for a head that is not a symbol |
| `["bind", "cd.name", [v, …], body]` | `OMBIND(OMS, OMBVAR(v, …), body)` |

For example, `integrate(f, x)` is
`["apply", ["calculus1.int", ["bind", "fns1.lambda", ["#2"], "#1"]], "#2"]`:
the antiderivative of the function `x -> f`, applied to `x`, since OpenMath
integrates functions and GIAC expressions.

### Writing GIAC input

From OpenMath, a consumer writes GIAC input text from the GIAC pattern and
`input`:

- `call`: `name(a1, a2, …)`;
- `infix`: `(a1) name (a2) …`, the node name between parenthesized
  arguments (`(a) xor (b)`, `(a) + (b) + (c)`); with one argument, `name(a1)`;
- `prefix`: `name(a1)`, for unary minus.

### Directions

`direction` says which way an entry may be used. Each direction is a
function: no two entries used to OpenMath have the same GIAC pattern, and no
two used from OpenMath have the same OpenMath pattern. When two GIAC nodes
mean the same symbol (`=` and `==` are both `relation1.eq`), one goes both
ways and the other only to OpenMath.

### Status

`names` means that the node and the symbol name the same operation with the
same arguments. That their domains, branch cuts and conventions agree has not
been checked; the note says what is known to differ. `checked` will mark the
entries whose meaning has been compared, with the evidence in the note.

## Refused

```toml
[[refused]]
giac = "irem"                  # the GIAC node, and/or
om = "integer1.remainder"      # the OpenMath symbol it is mistaken for
reason = "…"                   # why it is not mapped
example = "irem(a, b)"         # optional: GIAC input read as that node
```

A consumer must decline these, and any node or symbol the table does not
list, rather than guess.

## Statuses, private CDs and procedures (format 2)

A reader uses only `official` CDs unless its caller enables others; procedure
symbols are valid only as the head of the argument of `scscp1.procedure_call`
and never in a result. The rules are in [private-cds.md](private-cds.md).
